# ADR 0003 — UI-диспетчер

## Контекст

Рекордер и загрузчик вызывали колбэки из рабочих потоков, а UI обновлялся
через `self.after(0, ...)` из этих потоков. Tk не гарантирует безопасность
`after` из чужого потока; в диспетчере моделей было то же самое.

## Решение

`ui/dispatcher.py::UiDispatcher`:

- `post(callback, *args)` кладёт задачу в `SimpleQueue`;
- главный поток разбирает очередь в `after(33ms)`;
- исключения в колбэках логируются и не убивают цикл;
- `stop()` отменяет `after` и отбрасывает новые задачи.

Все worker-callback-и (`AudioRecorder.on_tick`, `Transcriber.submit`,
`ModelManagerWindow` download thread) только вызывают `post`.

## Последствия

- Единственный путь worker → Tk; это проверяется код-ревью и архитектурным
  правилом.
- Задержка обновления до ~33 мс; для прогресса и статуса незаметно.
- При закрытии окна очередь отбрасывается; незавершённые UI-обновления
  теряются, что нормально.
